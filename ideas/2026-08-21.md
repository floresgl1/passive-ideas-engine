### 2. Scaffold Host-Capability Guard Linter — [Leverage]
- competence: unlabeled
- labeled_at: —

**Idea:** A small CLI that scans generated-file patch scripts (starting with Flutter's
`configure_ios.py`-style scripts) for file-mutation steps that aren't preceded by a check on
whether the host environment could actually have produced the file being patched, flagging the
exact bug class fixed in golf this week — a Podfile patch that ran unconditionally and exited 1 on
Linux/CI hosts that never generate a Podfile in the first place.
**Leverages:** AI-assisted development workflow at the tooling level `[strong]`, specifically this
week's real fix and the macOS compile-check CI workflow it sits alongside.
**One new thing to learn:** Generalizing the specific Podfile-vs-Xcode precondition check into a
pattern-matchable rule ("this mutation assumes artifact X exists; is there a guard checking for
X first?") that applies to other generated-scaffold ecosystems, not just Flutter/iOS.
**Why it's worth it:** The bug and its fix already exist as reference material; the linter mostly
needs to recognize the same shape (unconditional mutation of a conditionally-generated file)
elsewhere, which is bounded, mechanical work with a clear buyer (anyone shipping post-generate
config scripts for cross-platform tooling in CI).
**First step today:** Write the one rule that would have caught this week's actual bug — flag any
script step that writes to a `Podfile` (or similarly host-generated file) without a preceding
existence/capability check — and run it against `configure_ios.py`'s pre-fix and post-fix versions
to confirm it fires on one and not the other.

### 3. The Compile-Check Blind Spot — [Passive]
- competence: unlabeled
- labeled_at: —

**Idea:** A short, sold-once written guide teaching layered verification for generated-code

**Leverages:** Epistemic discipline about one's own system `[strong]` (the meta-skill) as a

**Why it's worth it:** It's a content asset, written once and sold repeatedly, and the source
material — a real bug, a real weak guard, a real fix that closed the specific gap — is already
sitting in this week's shipped work rather than needing to be invented.
**First step today:** Write up this week's camera-permission-string bug as the guide's first
worked example: what the compile-check workflow verified, what it structurally could not verify,
and what the second script added to close that gap.

### 4. Agentic Framework Migration Spike — [Stretch]

- labeled_at: —

**Idea:** Take finance_bot's hand-rolled ReAct-style agent loop (bounded steps, retry budget,

**One new thing to learn:** Framework-based agent orchestration itself (CrewAI's task/agent/crew
model) — specifically how to reproduce the hand-rolled version's hard constraints (step caps,
finite retry budget, enumerated error categories) inside a framework that has its own opinions
about control flow, rather than losing that discipline in the port.
**Why it's worth it:** This is a stated, still-open Direction & Intent line, not an invented
stretch, and it's the one profile-identified gap between "can build a disciplined hand-rolled
agent" and "can also operate inside the frameworks most other teams already standardize on" — a
gap worth closing before it becomes a resume liability.
**First step today:** Reproduce finance_bot's exact step-cap and retry-budget behavior as a
minimal CrewAI task definition against a stub tool call, and confirm the same failure mode
(exceeding the cap) is still caught the same way before porting any real trading logic.
