## Ideas

### 1. Sub-agent guardrail pack — bounded-agent templates for Claude Code [Leverage]
**Idea:** Package the finance_bot/golf pattern of bounded, guardrailed sub-agents (step caps, retry budgets, enumerated error categories, silent-failure severity audits) as a documented, install-ready Claude Code sub-agent template pack, sold once per buyer on a template marketplace (Gumroad-style).
**Leverages:** LLM agent engineering [strong] + AI-assisted dev tooling [emerging] — this is close to a direct repackage of patterns already shipped twice.
**One new thing:** a packaging/licensing flow (versioned template distribution, buyer-facing docs) — no new engineering skill required.
**Why it's worth it:** fastest path to revenue of the four; near-zero net-new build risk since the underlying patterns are already proven in two repos.
**First step today:** extract the guardrail/error-taxonomy patterns from finance_bot's agent code into a domain-agnostic template file and write the install README.

### 2. Reconciliation-core as a licensable module [Passive]
**Idea:** Extract stripe-reconciler's double-entry/Suspense-account engine (Stripe payout → balanced journal, unknowns routed to Suspense) into a standalone library sold as a one-time license/template to indie SaaS builders who need correct-by-construction bookkeeping without building it themselves.
**Leverages:** Multi-tenant SaaS + reasoned security discipline [emerging/strong] and the domain-modeling rigor (integer cents, explicit Suspense over silent defaults) already shipped and tested.
**One new thing:** stripping tenant/UI coupling out so the core ships as a standalone importable package rather than an app.
**Why it's worth it:** a template/library sold repeatedly with no per-sale labor is the cleanest fit for "genuinely passive" of anything in the profile — the hard part (correctness) is already done and CI-tested.
**First step today:** identify the module boundary in stripe-reconciler's backend between the journal engine and the Flask/tenant layer, and sketch the extraction.

### 3. Movement-correctness API, second vertical [Experience]
**Idea:** Generalize the golf-swing-analyzer pipeline (pose estimation → phase segmentation → fault flags → corrective drills) into a form-check API for a second, distinct movement domain (e.g. physical-therapy rep form or a different sport), sold as a metered API to small fitness/PT apps.
**Leverages:** Computer vision on real footage [strong] and the diagnose→prescribe→verify loop already proven end-to-end in golf.
**One new thing:** generalizing the fault-flag/threshold layer so it's parameterized per-domain instead of golf-specific — the actual new skill is building a *reusable* engine, not a one-off pipeline.
**Why it's worth it:** the payoff isn't just this API — it's converting a single-domain pipeline into a multi-vertical engine, which compounds into future ideas the way stripe-reconciler's engine now does above.
**First step today:** audit golf's phase-segmentation and fault-flag code for what's genuinely golf-specific vs. what's already domain-agnostic, to scope the extraction.

### 4. Ship the circuit simulator's first slice — data model + DC solver [Stretch] 🔑 crosses the keystone
**Idea:** Un-stall the visual JS circuit simulator by shipping only its first two phases — data model and a modified-nodal-analysis (MNA) DC solver, with a minimal static visualizer — as a small embeddable teaching widget, monetized via a one-time license to bootcamps/educators or an accompanying build-log content channel.
**Leverages:** Software-delivery discipline proven across four repos (design docs before code, testing discipline, epistemic honesty about what's validated) applied for the first time to the hardware/analog direction.
**One new thing:** modified nodal analysis (MNA) — the specific numerical technique for solving a real circuit graph. One technique, not ten.
**Why it's worth it:** this is the keystone move named in the profile — it graduates the hardware axis from zero shipped inventory to one real artifact, which the profile flags as worth more than any single idea because several future ideas depend on it existing. It's also the one idea here that's a stretch on domain rather than on tooling, so it directly earns the "one new thing" budget.
**First step today:** answer the design question the simulator stalled on — pick the circuit data model (component/node graph schema) — and write it down as a one-page decision record before touching solver code.
