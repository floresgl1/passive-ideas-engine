## Step 3 — Ideas

### 1. Secure Multi-Tenant SaaS Starter Kit — **[Leverage]**
**Idea:** Package stripe-reconciler's tenant-isolated Flask+PostgreSQL/React19 scaffolding — CSRF origin checks, timing-equalized auth, digest-only reset tokens, tenant-isolation test suite — into a documented boilerplate sold repeatedly on a dev-tools marketplace.
**Leverages:** The shipped multi-tenant SaaS security architecture, near-verbatim.
**New thing to learn:** Packaging and licensing a template for external buyers (docs, demo, pricing) — not new tech.
**First step today:** Strip stripe-reconciler's domain logic out of a fork, leaving the auth/tenancy/security skeleton and its test suite intact as the sellable core.

### 2. Swing-Check API — **[Passive]**
**Idea:** Generalize the golf pipeline (pose estimation → phase segmentation → biomechanical fault flags → corrective drills) to a second sport and expose it as a usage-metered REST API for app developers.
**Leverages:** The measurement-pipeline capability plus FastAPI/REST design from visual-search-engine.
**New thing to learn:** Sport-specific biomechanics for the second domain (e.g., baseball swing or deadlift form).
**First step today:** Pick the second sport and list its 3–4 highest-value fault flags by analogy to golf's tempo/body-angle set, before touching code.

### 3. Unattended-Pipeline Watchdog — **[Experience]**
**Idea:** Extract finance_bot's observability pattern (staleness detection, halt-flag circuit breakers, transition-only alerting, severity-classified failure audits) into a standalone library + Discord/Slack alerting template sold to people running their own scheduled GitHub Actions pipelines.
**Leverages:** Production-observability discipline built for a single money-adjacent pipeline.
**New thing to learn:** Designing a general-purpose plugin/config interface instead of a hardcoded one — generalizing surfaces edge cases the single-use version never had to handle, which is exactly what hardens the underlying skill.
**First step today:** Pull the halt-flag and staleness-detection modules out of finance_bot into a separate package with no finance-specific imports, and see what breaks.

### 4. Circuit Sandbox — **[Stretch]** — ⚑ crosses the keystone
**Idea:** Finish the stalled visual JS circuit simulator through its solver phase (nodal analysis for resistive DC circuits) to a shippable v1, then license it as an embeddable interactive widget for hobby-electronics blogs and EE course sites.
**Leverages:** Proven software-delivery discipline (design-doc-first, phased architecture, tested) applied to `[conceptual]` circuit-analysis knowledge — explicitly a stretch, since no hardware line has shipped yet.
**New thing to learn:** Implementing a numeric linear-equation solver (modified nodal analysis) in JS — one new thing, not ten.
**Why the stretch is worth it:** The hardware/architecture axis currently has zero shipped inventory — it's all Direction & Intent. This is the one self-scoped, shovel-ready project that sits at the intersection of proven delivery capability and the hardware direction. Shipping it converts the keystone from direction to demonstrated capability and unlocks a whole category of hardware-shippable and hardware-teaching ideas that aren't reachable from the current profile.
**First step today:** Resolve the stalled opening design question by committing to the minimal spec (DC resistive circuits only, node-voltage method, 2D canvas) and write the circuit-graph data model (nodes + edges) as the first file.
