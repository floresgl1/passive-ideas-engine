### 2. Time-Series Leakage Auditor — [Passive]
- competence: unlabeled
- labeled_at: —

**Idea:** Build a small CLI/library that scans a Python data-science project's train/test-split
and cross-validation code for common time-series leakage patterns — random (non-chronological)
splits, target leakage via join keys, missing walk-forward retraining — and outputs a flagged
report, sold as a one-time-purchase tool to data scientists and bootcamp students.
**Leverages:** finance_bot's own walk-forward retraining and chronological-split discipline,
generalized from a rule this person follows into a rule a tool can check for someone else.
**One new thing to learn:** Static analysis of unfamiliar pandas/scikit-learn code well enough to
detect a non-chronological split or a leaking join, rather than just following the rule in code
already under full control.
**First step today:** Point a first-draft checker at finance_bot's own split logic and confirm it
correctly reports zero leakage findings — the honest baseline test before pointing it at anyone
else's code.
**Why it's worth it:** Leakage is the single most common way a time-series model looks good in
backtest and fails live; a tool that catches it mechanically sells repeatedly with no
per-customer labor once built, and it draws on a rule already proven correct in a live system.
