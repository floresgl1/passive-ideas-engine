# Daily Ideas — 2026-10-05

### 1. Spoken-Answer Grader API — [Passive]
- competence: unlabeled
- labeled_at: —

**Idea:** A paid API that takes a question, an expected answer, and a speech-to-text transcript and returns a structured correct/partial/incorrect verdict that forgives transcription artifacts (homophones, dropped units, mangled numbers), so any voice-learning or flashcard app can add fair grading without writing its own judge prompt.
**Leverages:** voice-quiz's Claude-graded spoken answers with leniency for transcription artifacts, plus the constrained-JSON judge outputs and FastAPI service work.
**One new thing to learn:** Calibrating a judge against a labeled set of real ASR errors and publishing its agreement rate, rather than just prompting it.
**Why it's worth it:** Every voice study app hits the same "the transcript is wrong, not the student" problem; a per-call API sells repeatedly with little upkeep once the judge is calibrated.

### 2. Speakable-Text Normalizer — [Leverage]
- competence: unlabeled
- labeled_at: —

**Idea:** A small pip/npm library that rewrites LaTeX, engineering notation (4.7kΩ, 10µF), and symbols into text that text-to-speech reads correctly, with an alt-text hook for diagrams.
**Leverages:** voice-quiz's math-to-speech and LaTeX-escape pass and its spoken diagram descriptions.
**One new thing to learn:** Packaging and publishing a library with a test corpus of tricky expressions to a package registry.
**Why it's worth it:** Quick to ship, since the core logic already exists, and it fills a gap for any TTS app that reads technical content.
