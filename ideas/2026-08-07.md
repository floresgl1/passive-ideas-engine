## Step 2–3 — Ideas

### 1. Threshold-Test Scaffolder — [Leverage]
- competence: unlabeled
- labeled_at: —

**Idea:** Build a CLI that scans a Python data/ML repo for threshold-sensitive functions (fault
flags, confidence cutoffs, classification boundaries) and scaffolds golden-fixture and
characterization tests around them, seeded with the same non-vacuous-test discipline already
proven across golf, finance_bot, and stripe-reconciler, sold once per buyer to solo ML/data
engineers.
**Leverages:** The already-shipped, cross-repo habit of writing threshold tests that can actually
detect a threshold change, rather than tests that pass regardless of the value.
**One new thing to learn:** Generalizing the "does this test detect a real change" check into a
static-analysis heuristic a tool can run automatically, instead of a manual review habit applied
by hand each time.
**Why it's worth it:** The hard-won judgment (what makes a threshold test meaningless) is already
proven in three shipped codebases; packaging it as a scaffolding tool turns a personal habit into
a repeatable, sellable artifact with no ongoing labor per sale.
**First step today:** Pull the golden-fixture pattern out of one of golf's or finance_bot's test
suites and write down, as a checklist, the exact property that made those specific tests
non-vacuous — that checklist is the tool's core logic.

### 2. Production-Ready Deploy Template — [Passive]
- competence: unlabeled
- labeled_at: —

**Idea:** Package the Docker/compose + gunicorn deployment pattern already shipped across
visual-search-engine, stripe-reconciler, and finance_bot — health checks, worker tuning,
environment-config separation, reproducible builds — into a documented starter template for
Flask/FastAPI apps, sold repeatedly on a dev-tools marketplace.
**Leverages:** The already-proven last-mile deployment discipline, demonstrated independently in
three separate production services rather than assembled for this purpose.
**One new thing to learn:** Generalizing service-specific gunicorn/health-check configuration
into parameterized, documented defaults a stranger's app can drop in without editing internals.
**Why it's worth it:** The template needs no maintenance once it's stable — it's the cleanest fit
for "genuinely passive" here, and the underlying deployment choices are already battle-tested in
three live services, not guessed at for this product.
**First step today:** Diff the Dockerfile/compose/gunicorn config across the three repos to find
what's already identical between them — that overlap is the template's default, and the
differences mark exactly what needs to become a configurable option.

### 3. Silent-Failure Self-Audit Tool — [Experience]
- competence: unlabeled
- labeled_at: —

**Idea:** Turn finance_bot's one-off severity-classified silent-failure audit into a reusable CLI
that scans a Python service for the same failure-mode class — unguarded excepts, missing
staleness checks, absent circuit breakers, untested thresholds — and outputs a severity-ranked
report, sold as a one-time tool to teams running unattended pipelines.
**Leverages:** Production observability and self-audit discipline already proven on a real,
money-adjacent running system, plus the epistemic-discipline meta-skill used here only to shape
the audit's criteria, never sold as the product itself.
**One new thing to learn:** Turning a manual, single-system audit into a generalized static check
that runs against code it has never seen — the audit criteria have to become explicit rules
instead of applied judgment.
**Why it's worth it:** The exercise itself hardens the most valuable and least common skill in the
profile — the discipline of finding what your own system doesn't know it's failing at — by forcing
it into a form that has to work on someone else's codebase, not just the one it was learned on.
**First step today:** List the specific failure categories finance_bot's audit actually found
(by severity), and mark which ones are detectable by a static grep/AST check versus which
genuinely require runtime behavior — that split scopes the v1.
