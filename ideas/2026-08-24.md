### 2. Silent-Failure Sentinel — [Passive]
- competence: unlabeled
- labeled_at: —

**Idea:** A hosted, metered service that watches a customer's scheduled job (cron, GitHub Actions, Airflow) and runs an LLM diagnostic agent to catch "ran but did nothing" failures — not just missed runs — the same class of bug `daily-run-triage` caught in finance_bot's own pipeline.
**Leverages:** Production observability and failure handling [strong] (`pipeline_status.py`, severity-classified silent-failure audits) plus LLM agent engineering [strong] (bounded steps, enumerated error categories) plus CI/CD automation [strong].
**One new thing to learn:** multi-tenant metered billing and alert delivery (Stripe usage-based billing, webhook/Discord/email fan-out) — the diagnostic core itself is already proven.
**Why it's worth it:** the diagnostic approach already found a real 5-day silent production bug once; "dead man's snitch"-style tools exist but stop at "didn't run," none do LLM-based root-cause diagnosis of jobs that ran and lied about success.
**First step today:** write a one-page, processor-agnostic version of `pipeline_status.py`'s health-snapshot schema (job name, last-success timestamp, expected cadence, log excerpt) that any customer's job could POST to an endpoint.

- labeled_at: —

**Idea:** Ship a minimal, read-only SVG schematic renderer that consumes circuit-simulator's existing netlist format and lays out components on a canvas — a deliberately small slice of the still-unshipped visualizer phase — sold as a small paid web tool for hobbyist circuit learners.

**Keystone:** crosses the keystone — even a render-only schematic view converts the "visual JS circuit simulator" direction from zero shipped visual output to a first shipped visual artifact, making phase-4 interactivity a much smaller next step.
