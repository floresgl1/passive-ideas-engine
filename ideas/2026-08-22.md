### 1. Deterministic Race Reproducer — [Experience]
- competence: unlabeled
- labeled_at: —

**Idea:** A small CLI/library that takes a suspected race condition in Python or C (a described
shared-resource access pattern) and automates the "insert a deliberate delay, run until the failure
reproduces" technique already used by hand twice — CSE4600-HW1's pthread race and stripe-
reconciler's cache-fill-outside-the-lock bug — turning a manual, one-off reproduction step into a
repeatable harness, then generating a regression test from whatever reproduces.
**Leverages:** Testing discipline `[strong]` and systems programming `[emerging]`, specifically the
two real instances of reproduce-before-fix already proven (a deliberate race in coursework, an
inserted-sleep reproduction of stripe-reconciler's live CI failure).
**One new thing to learn:** Generalizing "insert a delay by hand at the suspected contention point"
into a systematic search — varying delay placement and duration across candidate contention points
automatically instead of guessing the one spot to perturb.
**Why it's worth it:** The technique already works and has caught two real bugs; the only missing
piece is turning a manual step into a tool, which is bounded work with a clear buyer (anyone
chasing an intermittent concurrency bug they can't reliably reproduce).
**First step today:** Reproduce stripe-reconciler's original cache-fill race using the exact
inserted-sleep placement already used by hand, but driven by a first, hardcoded harness script
instead of a manually-edited sleep call — confirm the harness reproduces the same failure the
manual version did.
