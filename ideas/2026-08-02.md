# Idea Engine — 2026-08-02

## Step 1 — Abstracted capabilities (from [strong]/[emerging] shipped work only)

- **Signal-to-measurement pipelines**: turn a noisy real-world signal into a defensible measurement — physically-reasoned feature choice, scale-invariant normalization, correct math, and knowing the difference between a measurement and a verdict. *(golf-swing-analyzer)*
- **Unattended production operations**: run a system with real stakes hands-off — pre-flight validation, circuit breakers, staleness detection, transition-only alerting. *(finance_bot)*
- **Disciplined LLM agent engineering**: bounded steps, finite retry budgets, enumerated error categories, constrained output vocabularies, written v1 contracts. *(finance_bot)*
- **End-to-end SaaS delivery with the unglamorous parts done right**: reasoned security (not cargo-culted), disciplined domain modeling, tenant isolation as a first-class test suite. *(stripe-reconciler)*
- **Retrieval stack, exploration to deployable service**: embeddings, vector storage, similarity search, REST API, container — reproducible, not aspirational. *(visual-search-engine)*
- **Applied statistical reasoning under uncertainty** *(emerging→strong)*: CI lower bounds vs. a computed breakeven, sample-size intuition, leading/lagging separation.

*(Epistemic discipline — measurement-vs-verdict, holding divergence open, self-audited failure modes — is the meta-skill behind all of the above. It raises the bar on every idea below and appears only as a teaching angle in Idea 3, never as a product itself.)*

## Step 2 & 3 — Ideas

### 1. Motion-Coach Build Kit — [Leverage]
**Idea:** Package the golf-swing-analyzer's measurement architecture (pose landmarks → phase segmentation → fault flags → drills) as a generalized template + build guide for other single-camera sports-form problems (tennis serve, deadlift, pitching).
**Leverages:** The full diagnose-loop architecture already proven and shipped in golf-swing-analyzer.
**New thing to learn:** Generalizing landmark/phase logic to a second sport's biomechanics (one new motion domain, not a new pipeline).
**Worth it because:** Near-zero new capability risk — it's a repackaging of code and judgment that already works, sold once per buyer, indefinitely.
**First step today:** Pick one target sport with strong search demand (tennis serve is a good fit — similar single-plane phase structure) and outline which golf modules port directly vs. need new fault-flag logic.

### 2. Metered Niche Image-Search API — [Passive]
**Idea:** Deploy visual-search-engine publicly as a natural-language search API for one narrow vertical (e.g., interior/real-estate photo libraries or textile/pattern stock), billed per query.
**Leverages:** The CLIP+ChromaDB+FastAPI retrieval stack (visual-search-engine) plus the double-entry billing rigor from stripe-reconciler for usage metering.
**New thing to learn:** Stripe metered/usage-based billing (a new billing model, not a new stack).
**Worth it because:** Once deployed, it runs unattended — the passive-income filter this profile is best positioned to hit cleanly, since both halves (search + billing discipline) are already shipped independently.
**First step today:** Pick the vertical and source/license a starter image set (500–2,000 images) to re-embed and index.

### 3. "Systems That Admit What They Don't Know" mini-course — [Experience]
**Idea:** A short paid course/newsletter teaching the epistemic-discipline pattern (measurement vs. verdict, held-open divergence, halt flags) through concrete case studies pulled from golf, finance_bot, and stripe-reconciler.
**Leverages:** The epistemic through-line as a teaching wedge — explicitly a content/teaching angle, not "my judgment as a service."
**New thing to learn:** Structuring and shipping an evergreen teaching asset (course platform, pricing, cohort-free delivery) — a packaging skill, not a technical one.
**Worth it because:** Forces the pattern into explicit, transferable language, which sharpens it for every future project — the product is the writeup, never the judgment itself.
**First step today:** Draft the case-study outline for one system (start with finance_bot's halt-flag/staleness design, since it's the most concrete and already documented).

### 4. Minimal Browser Circuit Simulator (Phase 1 only) — [Stretch] ⭐ crosses the keystone
**Idea:** Ship just the data-model + basic DC solver phases (1–2 of the 5 self-scoped phases) of the stalled visual JS circuit simulator, wrapped as an embeddable teaching widget sold to EE educators/bootcamps.
**Leverages:** Proven software-delivery discipline (design-doc-first, phased architecture) applied to the already-scoped-but-stalled circuit simulator design.
**New thing to learn:** A real linear-circuit solver (nodal analysis) implemented in JS — one concrete algorithm, not the full 5-phase system.
**Why the stretch is worth it:** This is the single highest-leverage move available in the whole profile — the hardware/architecture axis currently has zero shipped inventory, and shipping even Phase 1 converts it from [conceptual] to [strong], unlocking every future hardware-adjacent idea this profile can't currently support.
**First step today:** Unblock the stalled opening design question — write the minimal data model for nodes/branches/sources needed for nodal analysis, scoped to resistors + DC sources only (skip dependent sources for v1).
