### 1. Semantic Video Moment Search — [Leverage]
- competence: unlabeled
- labeled_at: —

**Idea:** Extend visual-search-engine's CLIP + ChromaDB + FastAPI stack to index video instead of
static images — extract frames at a fixed interval with timestamps (the same ffmpeg/OpenCV
handling already proven in golf's pipeline), embed each frame, and return ranked timestamps for a
natural-language query — sold as a paid API to podcasters, course creators, and video archives who
need "find the moment X happens" search across long-form footage.
**Leverages:** The already-shipped CLIP/ChromaDB/FastAPI retrieval stack from visual-search-engine
plus the video frame-extraction and CV pipeline discipline already proven in golf — two shipped
stacks combined for the first time rather than either pitched alone.
**One new thing to learn:** Temporal indexing — attaching timestamp metadata to each embedded
frame and returning a ranked, timestamp-ordered result set for a query, instead of visual-search-
engine's existing flat image-to-image/text similarity search.
**Why it's worth it:** Both halves of this are already shipped and tested; the only genuinely new
work is the timestamp-indexing layer, which is a small, bounded addition on top of infrastructure
that already runs end to end.
**First step today:** Write a script that extracts frames at 1fps from one sample video with
ffmpeg, embeds each with visual-search-engine's existing CLIP pipeline, and confirms a
natural-language text query returns the correct timestamp on that one video.

### 2. Webhook Reliability Test Harness — [Passive]
- competence: unlabeled
- labeled_at: —

**Idea:** Package the specific webhook-security discipline already reasoned and tested in
stripe-reconciler — signature verification, timing-attack equalization, the documented CSRF
webhook exemption — as a CLI tool that fires unsigned, replayed, out-of-order, and malformed
payloads at any developer's own webhook endpoint URL and reports which attack classes it's
vulnerable to, sold as a one-time license to SaaS developers integrating Stripe or similar
webhook providers.
**Leverages:** Applied web application security `[strong]`, specifically the exact attack classes
stripe-reconciler's own test suite already defends against, redirected from an inward-facing test
suite to an outward-facing attack simulator.
**One new thing to learn:** Building a generic attack-payload generator that targets someone
else's endpoint from the outside, as a black-box client — a different vantage point than any test
written so far, which has all tested code from the inside.
**Why it's worth it:** This is a narrower, faster build than a code scanner (already mined as
Migration Review Bot and Security-Pattern Repo Scanner) because it needs no access to the buyer's
source — it only sends HTTP requests and reads responses, so it's usable by anyone with a URL.
**First step today:** List the exact attack classes stripe-reconciler's own webhook tests already
cover (missing signature, replayed payload, stale timestamp window) and write the first
sender — an unsigned-payload request — against a local test endpoint.
