## Step 2–3 — Ideas

### 1. Near-Duplicate Image Detector API — [Leverage]
- competence: unlabeled
- labeled_at: —

**Idea:** Repackage visual-search-engine's CLIP + ChromaDB + FastAPI + Docker stack as a
metered "find duplicate/near-duplicate images" API, sold to stock-photo marketplaces,
print-on-demand platforms, and listing sites that need to catch reposted or lightly-edited images.
**Leverages:** The already-shipped retrieval stack (embeddings → vector store → REST API →
container) — this is closer to a direct redeploy than new engineering.
**One new thing to learn:** Calibrating a similarity-threshold methodology that separates
"same image, re-encoded/cropped" from "genuinely different but similar" — a focused tuning
problem, not new infrastructure.
**Why it's worth it:** The hard part (a working, containerized retrieval service) is done and
was never used as the core of a prior idea — this is close to pure productization.
**First step today:** Fork visual-search-engine, strip the collection down to a synthetic set
of originals + edited duplicates (crop/recolor/watermark), and measure the cosine-similarity
gap between true duplicates and near-neighbors to see where a threshold would sit.

### 2. CI Hardening Starter Kit — [Passive]
- competence: unlabeled
- labeled_at: —

**Idea:** Package the CI/CD pattern already proven twice (concurrency groups, caching,
fail-closed-when-no-suites-found, scheduled workflows with staleness/halt-flag checks) as a
documented GitHub Actions template bundle, sold once per repo/org on a template marketplace.
**Leverages:** CI/CD and scheduled-automation discipline plus production-observability patterns

alert destinations) into configurable workflow inputs so it drops into an unfamiliar repo.
**Why it's worth it:** A template sold repeatedly with no per-sale labor is the cleanest fit
for genuinely passive income, and the underlying pattern is already CI-tested in two repos.
**First step today:** Diff finance_bot's and stripe-reconciler's `.github/workflows/` files to
extract the parts that are identical in spirit but hardcoded differently, and turn those into
one composite/reusable workflow with inputs.
